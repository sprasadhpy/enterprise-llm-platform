Memory Management in EntainGPT

How we extended effective conversational context while remaining within model token limits, from Rolling Summary v1.0 through Dynamic Memory exploration.

Overview

Large language models (LLMs) often face context-length limitations when managing long, multi-turn conversations. Once the conversation history grows beyond the model's token window, it risks losing prior information or encountering throttling errors.

To address this, we introduce a lightweight technique called Rolling Summary Evaluation in version V1.0. A method that continuously compresses earlier dialogue turns into concise, system-generated summaries. This allows the conversation to continue seamlessly without sacrificing important context.

Rolling Summary V1.0

How It Works

Dataset Selection

We evaluate the approach using the EdinburghNLP/XSum dataset. A single-sentence summarization benchmark where each BBC article is paired with a concise, human-written summary. This setup offers a clear structure for assessing how effectively a rolling summary can preserve key information.

Our Design: Rolling Summary Mechanism

The system maintains a running list of conversation messages (ChatMessage objects). When the list exceeds a predefined threshold (for example, 8 messages), the following logic applies:

  1. Retain the latest three messages verbatim.
  2. Preserve any messages containing file attachments or structured event data.
  3. Compress older plain-text messages using a summarization model (e.g., Claude 4), producing a 3-5 sentence summary under 100 words.
  4. Insert the summary as a new system message in the format: "Previous conversation summary: <text>"
Key Insight: This design significantly reduces the token footprint while maintaining narrative continuity.

Evaluation Pipeline

Input Preparation

Each XSum article is split into sentences, and every sentence is treated as a sequential "user message" within the rolling-summary pipeline, simulating a multi-turn dialogue.

Prediction

The apply_rolling_summary function processes these messages, dynamically inserting summaries as the context grows. The resulting system-generated summaries form the model's predicted outputs.

Reference

The dataset's human-written summary serves as the ground-truth reference for evaluation.

Metrics

  • ROUGE-1 / ROUGE-2 / ROUGE-L - measures n-gram overlap between generated and reference summaries.
  • BERTScore - evaluates meaning preservation through contextual embeddings, capturing semantic fidelity beyond surface text overlap.

Insights

The results show that rolling summaries effectively preserve the essence of long conversations. Aggregate ROUGE scores demonstrate that the compressed summaries retain most of the key information from the original text, while BERTScore confirms that the models capture semantic meaning even when phrasing diverges from the human-written reference.

In practice, this means the summarization mechanism allows the model to "remember" critical context without carrying the full conversational load.

Benefits

Scalability

Enables sustained multi-turn conversations without exceeding token limits.

Cost Efficiency

Reduces inference tokens, leading to faster and more economical model runs.

Continuity

Maintains coherent context over time, ensuring the assistant remains grounded in previous exchanges.

While Rolling Summary v1.0 established an efficient compression mechanism for dialogue, it was optimized primarily for short, text-only interactions. EntainGPT v2.0 extends this foundation, introducing smarter context control and robust file-handling mechanisms to support enterprise-scale use cases.

LongContext+ : Rolling Summary for EntainGPT V2.0

Design Evolution

Modified Rolling Summary

The v2.0 architecture retains the same ChatMessage-based rolling mechanism, but now operates on character length instead of message count. When the message history exceeds 500,000 characters:

  1. Keep the latest three messages verbatim
  2. Retain any structured or file-linked messages
  3. Pass older plain-text content to Claude 4 for summarisation (3-5 sentences under 100 words)
  4. Insert the output as a single system message: "Previous conversation summary: <text>"
This approach balances continuity and compression across large, multi-modal conversations.

File Handling and Large-Context Resilience

Large file uploads can easily trigger context-window overflow at the ChatCompletion endpoint. Version 2.0 introduces a structured workaround:

  1. Character Check: Measure len(chars) of the uploaded file.
  2. Conditional Split:
    • If len(chars) ≤ 200,000, process the file directly.
    • If len(chars) > 200,000, split the file into head and tail sections.
  3. Recursive Chunking:
    • If the tail still exceeds 500,000 characters, subdivide it into smaller chunks.
    • Each chunk is summarised individually by Claude 4, and summaries are concatenated sequentially.

This ensures no section of the file is lost, while preserving semantic continuity and avoiding throttling errors, effectively enabling infinite-length memory simulation.

Outcomes

Reliability

No throttling or token-limit errors even for > 500K character files.

Scalability

Supports extended multi-turn interactions across documents, logs, and knowledge bases.

Efficiency

Maintains consistent summarisation quality (ROUGE ≈ v1.0 levels) while improving throughput.

Flexibility

Seamlessly integrates with EntainGPT's RAG and knowledge-retrieval pipelines.

Exploring MemGPT (Letta) for Stateful Memory

Letta is an open-source framework designed to build stateful AI agents with advanced memory and reasoning capabilities. Unlike traditional large language models that operate statelessly, Letta enables agents to remember past interactions, learn from them, and evolve over time. Formerly known as MemGPT, it provides a comprehensive foundation for developing intelligent agents that can maintain context across sessions and perform complex tasks autonomously.

Core Concepts

Stateful Agents

Letta transforms LLMs into persistent, memory-retaining agents. These agents maintain context across interactions, enabling coherent and adaptive responses over long-term engagements such as virtual assistants and customer-support systems.

Advanced Memory Management

Inspired by operating-system memory hierarchies, Letta structures its memory into three layers:

  • In-context memory: temporary storage for active conversations.
  • Persistent memory: long-term retention across sessions.
  • External memory: connections to databases and APIs for additional knowledge.

This layered design allows efficient handling of large information volumes, overcoming the context-window limits typical of LLMs.

Model-Agnostic Framework

Letta works across major model providers (OpenAI, Anthropic, and open-source variants), allowing developers to select the best fit without vendor lock-in.

Tool Use and Multi-Agent Collaboration

Agents can call external tools or APIs, expanding beyond text generation into data-driven reasoning. Letta also supports multiple agents that share memory and coordinate on complex workflows.

Development Environment

  • Agent Development Environment (ADE): A graphical IDE for creating, testing, and monitoring stateful agents. Developers can prototype through a no-code interface and inspect agent state in real time.
  • SDKs and Deployment: Python and TypeScript SDKs, plus a REST API, make integration straightforward. Agents can run locally via Docker or be deployed on Letta Cloud for managed hosting.
  • Agent File (.af) Format: An open format to serialize an agent's system prompts, memory configuration, tool hooks, and model settings, enabling reproducibility and version control across frameworks.

Our Takeaway

We explored the MemGPT/Letta architecture as part of our broader effort to bring user-level memory to EntainGPT. The framework illustrates how layered memory systems, combining in-context, persistent, and external storage, can enable agents to recall, learn, and evolve across sessions.

While our current infrastructure does not yet support stateful memory at this scale, this exploration offered valuable insight into how such systems might integrate into future versions of EntainGPT.

We also examined an alternative research direction, particularly the approach outlined in "Keep Me Updated! Memory Management in Long-term Conversations" (arXiv:2210.08750), to better understand emerging strategies for long-term context retention and structured memory management.

Dynamic Memory: "Keep Me Updated"

Building on LongContext+ which compresses earlier turns into rolling summaries, our next exploration focuses on Dynamic Memory. Unlike traditional summarization-based memory, Dynamic Memory treats the conversation as a living state that evolves over time. It introduces the ability to modify or discard outdated information as new facts emerge, mirroring how human memory adapts through revision rather than accumulation.

Key Concepts

  • The authors define a memory store as unstructured text descriptions of key information extracted from dialogues.
  • Memory can become outdated (e.g. user says "I have a sore throat" then later "I'm all better") and if you keep old memory, the bot may generate contradictions.
  • They define 4 operations to manage memory between old and new: PASS, REPLACE, APPEND, DELETE.
  • E.g. if new memory says "just got positive result from COVID test", old memory "haven't got tested" must be replaced.
  • They ran human/automatic evals over multiple sessions and show memory updating gives better "humanness" and "engagingness" as sessions progress.

Analysis

Overall, Rolling Summary performs better on ROUGE-1 and ROUGE-L, indicating stronger retention of key ideas and structural coherence across conversations. Dynamic Memory shows slightly higher ROUGE-2 scores in some models, suggesting tighter semantic linkage between turns, though its overall summarization quality remains lower.

The latency difference is notable: Dynamic Memory is 3-6x slower, reflecting its higher computational overhead. Across both methods, Claude 4 and GPT-5.1-nano deliver the most balanced trade-off between quality and efficiency.

While Rolling Summary is more scalable for production use, Dynamic Memory remains a promising direction for stateful, long-term reasoning agents such as persistent conversational companions, albeit slower and more resource-intensive, and still under active evaluation.
