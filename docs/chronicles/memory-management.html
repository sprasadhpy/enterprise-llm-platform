Memory Management in EntainGPT

How we extended effective conversational context while remaining within model token limits, from Rolling Summary v1.0 through Dynamic Memory exploration.

Overview

Large language models (LLMs) often face context-length limitations when managing long, multi-turn conversations. Once the conversation history grows beyond the model's token window, it risks losing prior information or encountering throttling errors.

To address this, we introduce a lightweight technique called Rolling Summary Evaluation in version V1.0. A method that continuously compresses earlier dialogue turns into concise, system-generated summaries. This allows the conversation to continue seamlessly without sacrificing important context.

Rolling Summary V1.0

How It Works

Dataset Selection

We evaluate the approach using the EdinburghNLP/XSum dataset. A single-sentence summarization benchmark where each BBC article is paired with a concise, human-written summary.

Our Design: Rolling Summary Mechanism

The system maintains a running list of conversation messages (ChatMessage objects). When the list exceeds a predefined threshold (for example, 8 messages), the following logic applies:

  1. Retain the latest three messages verbatim.
  2. Preserve any messages containing file attachments or structured event data.
  3. Compress older plain-text messages using a summarization model (e.g., Claude 4), producing a 3-5 sentence summary under 100 words.
  4. Insert the summary as a new system message in the format: "Previous conversation summary: <text>"
Key Insight: This design significantly reduces the token footprint while maintaining narrative continuity.

Evaluation Pipeline

Input Preparation

Each XSum article is split into sentences, and every sentence is treated as a sequential "user message" within the rolling-summary pipeline, simulating a multi-turn dialogue.

Prediction

The apply_rolling_summary function processes these messages, dynamically inserting summaries as the context grows.

Reference

The dataset's human-written summary serves as the ground-truth reference for evaluation.

Metrics

  • ROUGE-1 / ROUGE-2 / ROUGE-L - measures n-gram overlap between generated and reference summaries.
  • BERTScore - evaluates meaning preservation through contextual embeddings.

Insights

While Rolling Summary v1.0 established an efficient compression mechanism for dialogue, it was optimized primarily for short, text-only interactions. EntainGPT v2.0 extends this foundation, introducing smarter context control and robust file-handling mechanisms.

LongContext+ : Rolling Summary for EntainGPT V2.0

Design Evolution

Modified Rolling Summary

The v2.0 architecture retains the same ChatMessage-based rolling mechanism, but now operates on character length instead of message count. When the message history exceeds 500,000 characters:

  1. Keep the latest three messages verbatim
  2. Retain any structured or file-linked messages
  3. Pass older plain-text content to Claude 4 for summarisation (3-5 sentences under 100 words)
  4. Insert the output as a single system message: "Previous conversation summary: <text>"

File Handling and Large-Context Resilience

Large file uploads can easily trigger context-window overflow. Version 2.0 introduces:

  1. Character Check: Measure len(chars) of the uploaded file.
  2. Conditional Split: If ≤ 200,000 chars, process directly. If > 200,000, split into head and tail.
  3. Recursive Chunking: If the tail exceeds 500,000 chars, subdivide into smaller chunks. Each is summarised individually and concatenated.

Outcomes

Reliability

No throttling or token-limit errors even for > 500K character files.

Scalability

Supports extended multi-turn interactions across documents and knowledge bases.

Efficiency

Maintains consistent summarisation quality (ROUGE ≈ v1.0 levels).

Flexibility

Seamlessly integrates with EntainGPT's RAG pipelines.

Exploring MemGPT (Letta) for Stateful Memory

Letta is an open-source framework designed to build stateful AI agents with advanced memory and reasoning capabilities. Formerly known as MemGPT, it enables agents to remember past interactions and evolve over time.

Core Concepts

Stateful Agents

Letta transforms LLMs into persistent, memory-retaining agents maintaining context across interactions.

Advanced Memory Management

  • In-context memory: temporary storage for active conversations.
  • Persistent memory: long-term retention across sessions.
  • External memory: connections to databases and APIs.

Model-Agnostic Framework

Works across OpenAI, Anthropic, and open-source models without vendor lock-in.

Tool Use and Multi-Agent Collaboration

Agents can call external tools and coordinate on complex workflows.

Development Environment

  • Agent Development Environment (ADE): Graphical IDE for creating and monitoring stateful agents.
  • SDKs and Deployment: Python/TypeScript SDKs, REST API, Docker, or Letta Cloud.
  • Agent File (.af) Format: Open format for serializing agent config.

Our Takeaway

We explored MemGPT/Letta as part of bringing user-level memory to EntainGPT. While our infrastructure doesn't yet support stateful memory at this scale, it offered valuable insight for future versions.

We also examined "Keep Me Updated! Memory Management in Long-term Conversations" (arXiv:2210.08750) for emerging strategies in structured memory management.

Dynamic Memory: "Keep Me Updated"

Building on LongContext+, Dynamic Memory treats conversation as a living state that evolves over time, modifying or discarding outdated information as new facts emerge.

Key Concepts

  • Memory store as unstructured text descriptions of key information from dialogues.
  • Memory can become outdated, causing contradictions if not updated.
  • 4 operations: PASS, REPLACE, APPEND, DELETE.
  • Human/automatic evals show memory updating gives better "humanness" and "engagingness".

Analysis

Rolling Summary performs better on ROUGE-1 and ROUGE-L, indicating stronger retention of key ideas. Dynamic Memory shows slightly higher ROUGE-2 in some models but lower overall quality. The latency difference is 3-6x slower for Dynamic Memory.

While Rolling Summary is more scalable for production use, Dynamic Memory remains a promising direction for stateful, long-term reasoning agents.
